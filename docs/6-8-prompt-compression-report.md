# 6-8 Prompt 压缩实验报告

本文记录对 `entity_eval/agent.py` 中 `SYSTEM_PROMPT` 做压缩后的效果对比。

## 改动内容

将 prompt 从 ~89 行压缩到 ~43 行，保留 4 个区块：任务定义、必须输出、明确不输出、一个短示例。移除大量重叠规则（详见 `entity_eval/agent.py:13-55`）。

## 对比条件

- 同一 random seed 444、batch 100
- 6-5：原版 prompt（含后处理 11 个 filter pattern）
- 6-8：压缩版 prompt（后处理 filter pattern 未改动）

## 指标对比

| 指标 | 6-5 | 6-8 | 变化 |
|------|-----|-----|------|
| wall_clock | 60.8s | 42.8s | **-30%** |
| avg_duration | 2.48s | 1.89s | **-24%** |
| prompt_tokens 总计 | 183,759 | 111,359 | **-39%** |
| completion_tokens 总计 | 12,879 | 8,900 | **-31%** |
| 原始实体数 | 180 | 132 | -27% |
| 后处理过滤 | 17 | **0** | 不需要了 |
| 合并后实体 | 163 | 131 | -20% |
| 成功/失败 | 100/0 | 100/0 | 一致 |

每 call 系统 prompt 节省约 **724 token**（= 压缩掉的部分）。

## 实体一致性观察

对于有真实舆情事件的实体抽取量保持一致：

| doc_id | 6-5 | 6-8 | 说明 |
|--------|-----|-----|------|
| 2025021921788043422 | 22 | 22 | 一致 |
| 1a20206a4c35... | 10 | 10 | 一致 |
| 1913eb1187b0... | 10 | 10 | 一致 |
| 1c7ebcd9d650... | 2 | 2 | 一致 |
| 16f28521a08a... | 6 | 6 | 一致 |

边缘文章（名单/品牌/交易数据）新 prompt 在 LLM 层面自动过滤，不再依赖后处理：

| doc_id | 6-5 | 6-8 | 说明 |
|--------|-----|-----|------|
| 2025022100002644875 | 7（后处理滤 2） | 0 | 金价品牌提及，直接不抽 |
| 2025022421772017372 | 5（后处理滤 2） | 0 | 共同偏爱股票名单，直接不抽 |
| 159537783656... | 7（后处理滤 2） | 0 | 沪深港通纯交易数据，直接不抽 |

## 结论

- 压缩后的 prompt 效果正面：token 省 35-40%，时间省 30%，边缘实体在 LLM 层面自过滤。
- 零后处理过滤 = prompt 与 filter pattern 已对齐，后处理变成安全兜底而非主力。
- 对真正有舆情实体的文章，抽取量完全一致，无退化。
- 建议跑一轮 judge 确认 precision 是否有变化。
