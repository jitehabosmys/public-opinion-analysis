# 发现与后续计划

## 1. 现有标签复盘

### 原始标签 = 文章级整体情感

原始数据中的 `doc_sentiment`（正面/中性/负面）是对整篇文章的**全局情感打分**，存在以下问题：

| 问题 | 示例 | 影响 |
|------|------|------|
| **无法区分多实体** | 苹果用自研基带取代高通 → 全文标"中性"，但对高通是负面，对苹果是正面 | 多实体时标签失真 |
| **包含非金融内容** | 芦笋丰收、蛋糕店温情故事、个人支付宝被盗 → 被标为正面/负面 | 与金融风险无关，污染数据 |
| **标签质量参差** | 快手中性(0.73) - 实际降成本属正面；中汽协正面(0.56) - 内容偏中性 | 低分样本置信度存疑 |

**结论：现有标签可以作为单实体样本的参考 baseline，但不能作为金标准。我们最终输出是多实体展开的结构化风险数据，与原文难以直接对标。**

### 原始情感是谁的情感？

通过抽查多类样本确认：**大部分是客观事件走向**，而非报道者主观语气。金融新闻的记者语气基本是中性客观的（财报公告、股价变动等），标签实际反映的是"这件事对相关方好不好"。

## 2. 改造方案

### 核心思路：文章级 → 实体级

```
改造前: 1 条新闻 → 1 个情感标签
改造后: 1 条新闻 → N 行实体记录（按实体展开）
```

### 阶段性数据字段设计

#### 阶段一（核心）

| 字段 | 说明 |
|------|------|
| `doc_id` | 原文 ID，关联回原始数据 |
| `entity` | 提取的实体名称（公司/人名） |
| `financial_relevance` | 是否与金融风险相关（是/否）—— 不相关的直接过滤 |
| `entity_sentiment` | **利好** / **中性** / **利空** —— 事件对该实体的客观影响方向 |
| `impact_level` | 影响程度：**大** / **中** / **小**（中性时留空） |
| `sentiment_reason` | 情感判断的简要理由，如"净利润同比+108%，大幅超预期" |

#### 阶段二（扩展）

| 字段 | 说明 |
|------|------|
| `risk_type` | 风险/利好类别（财务/合规/经营/市场/声誉） |

#### 阶段三（完整报告）

| 字段 | 说明 |
|------|------|
| `event_summary` | 事件摘要（一句话） |
| `measure_template` | 应对措施模板（利空时）或机会建议（利好时） |
| `related_events` | 关联事件（利用 rel_id 聚类） |

### 与原始标签对比策略

仅对**单实体样本**（一篇文章只涉及一个公司）做对比，作为参考：
- 一致性高的样本 → 可辅助验证
- 不一致的样本 → 分析偏差来源，迭代改进

## 3. 下一步做什么

1. 用 LLM 在抽样集上试跑阶段一（实体提取 + 金融相关性 + 实体级情感）
2. 人工校验质量，迭代 prompt
3. 扩大到全量数据，落地到结构化格式
