## 3. rel_id 深度分析

`rel_id` 有**两种类型**，各约一半：

### 类型 A：日期前缀型（46.1%，23,072 条）

格式：`YYYYMMDD` + 序列号，例如 `2025022521790057693`

- **前 8 位**：事件主日期（与 `pub_date` 基本一致）
- **后续数字**：内部序列号，含义不明
- **作用**：将同一公司/事件的报道聚类。例如 `2025022521790057693` 下 4 条报道分别来自 4 个来源，均报道**尊界 S800 / 江汽集团测试争议**
- **异常**：1,063 条（4.6%）的日期前缀与 `pub_date` 不匹配，说明事件可能跨天报道

**结论：日期前缀型 rel_id 可用于辅助识别报道的"对象"（公司/事件）**

### 类型 B：32 位 Hash 型（50.7%，25,370 条）

格式：32 位十六进制 MD5-like 哈希

| 情况 | 数量 | 说明 |
|------|------|------|
| rel_id == doc_id（孤立） | 24,157 | 占 hash 型的 95.2%，rel_id 仅是 doc_id 的副本 |
| rel_id != doc_id，但 rel_id 是同一来源另一文章的 doc_id | 3,576 | 同一来源内的同批次关联 |
| rel_id 不是任何 doc_id | 81 | 极小例外 |

群组分布：
- size=1（孤立文章）：24,157 组
- size>=2（实际聚类）：222 组
- 最大群组：89 篇文章（均来自新浪新闻 APP）

**结论：hash 型 rel_id 主要是 doc_id 的副本，聚类价值极低。仅 222 个群组真正有意义，且为来源级而非事件级聚类。**

### 类型 C：其他（3.1%，1,558 条）

非以上两种格式的 rel_id，可忽略。

## 4. 数据质量问题

| 问题 | 详情 |
|------|------|
| 情感不平衡 | 正面 44.6% / 中性 40.6% / 负面 14.9% |
| 情感置信度 | 最低 0.35（部分为 0），需过滤低置信度样本 |
| author 缺失 | 29.7% 缺失 |
| 来源集中 | Top1 同花顺财经占 21%，Top3 合计占 40% |
| 区域集中 | 中央+华东合计占 85% |
| 正文长度差异大 | 最短 4 字符，最长 19,573 字符 |
| 缺少"对象"字段 | 没有显式标注报道涉及的公司/实体，需 NER 提取 |

## 5. 后续方向

1. **情感分类模型**：处理正/中/负不平衡（关注负面类）
2. **实体识别（NER）**：从标题/正文提取报道对象（公司名、人名）
3. **事件聚类特征**：利用日期前缀 rel_id 的事件分组信息
4. **结构化风险报告**：结合分类和 NER 结果，生成风险措施模板
