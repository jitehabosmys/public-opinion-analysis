# Eval 迭代记录：batch_30_eval_1 到 batch_30_eval_5

本文记录 6 月 5 日围绕实体抽取 `entity_eval` 和评测 `judge` 的迭代过程、每版目标、结果变化和当前结论。

## 背景

项目目标是把新闻文章从“文章级情感”改造成“实体级舆情结构化记录”：

```
1 篇新闻 -> N 个商业实体 -> 每个实体独立判断利好 / 中性 / 利空
```

当前阶段处理的是前 30 条样本，输入数据为：

- `data/test_news_0603.csv`
- 输出目录：`output/6-5/`
- 模型：`deepseek-v4-flash`
- thinking：disabled

核心问题不是单纯 NER，而是要区分：

- 有具体舆情事件或业务影响的商业实体，应输出。
- 仅提及、名单、客户案例、媒体来源、商品、指数、个人、政府机构等，不应输出。

## eval_1：宽松抽取，问题暴露

### 状态

`eval_1` 的 prompt 仍偏向“提取文章中提到的所有金融实体（公司、机构、品牌）”。结果是覆盖很宽，但噪声明显。

### 结果

- 实体数：133
- 有实体文章：29/30
- judge precision：0.883
- judge extra：33

### 主要问题

1. 列表型文章实体爆炸。

`2025上海网站制作公司哪家好?十家优秀网站设计公司名单揭晓` 抽出 42 个实体，包括大量客户案例、学校、品牌和服务案例。该文章贡献了全部实体的约三分之一。

2. 非商业实体或不应输出对象被抽出。

典型包括：

- `工业硅`
- `萤石矿`
- `KEKIUS`
- `狗狗币`
- `陈德军`
- `陈小英`
- `新加坡国家人工智能计划`

3. “仅提及”被当成中性实体。

不少实体只是背景、来源、客户案例或对比对象，但被标为中性。

4. 同一实体重复。

氪星晚报中 `阿里巴巴` 出现两行，分别来自不同事件或产品映射，但同为利好，应合并。

## eval_2：收紧“真中性”和仅提及过滤

### 改动

prompt 中明确：

- 只输出有具体舆情事件或业务影响的商业实体。
- 区分“真中性”和“仅提及”。
- 仅提及、客户名单、案例展示、媒体来源、商品、币种、指数、个人、政府机构等不输出。
- 同公司同方向应合并。

### 结果

- 实体数从 133 降到 48。
- 有实体文章从 29 降到 21。
- judge precision 从 0.883 提升到 0.973。
- judge recall 从 0.808 降到 0.725。

### 改善

明显压住了抽多问题：

- 网站制作公司名单从 42 个实体降到 0。
- `工业硅`、`萤石矿`、`KEKIUS`、`狗狗币`、个人名等被清理。
- 同向重复实体消失。

### 新问题

收紧过头，误杀了一些本应保留的具体事件：

- `追觅科技`：新品发布。
- `国泰基金`：基金发售。
- `中萤发展有限公司`：矿山扩建获批。
- `浪琴表`：新品发布。
- `温州市壹佳壹文化传媒有限公司`：项目执行单位选定。

## eval_3：补充“具体事件边界”

### 改动

prompt 中补充应输出的具体事件边界：

- 新品发布、产品升级、产品登榜。
- 基金/理财产品发行、发售。
- 项目获批、环评受理、产能扩建、投产。
- 融资、中标、收购、重组、股权转让。
- 投诉、处罚、诉讼、事故、质量问题。
- 业绩、股价、资金流、评级、回购、减值。

同时继续排除：

- 客户名单、服务案例、合作案例。
- 泛泛客户关系或供应关系。
- 对比对象、历史类比、竞品背景。
- 研报发布方、媒体来源、数据来源、提问平台。

### 结果

- 实体数：47
- 有实体文章：23

### 改善

追回了部分合理实体：

- `追觅科技`
- `国泰基金`
- `浪琴表`
- `中萤发展有限公司`
- `*ST美谷` 的部分重组参与方

### 问题

仍误杀了：

- `温州市壹佳壹文化传媒有限公司`

原因是政府或事业单位相关项目的边界还不够清楚。文章中的采购方是事业单位，但商业承接方应输出。

## eval_4：补强政府采购/项目承接方边界

### 改动

prompt 中补充：

- 融资、中标、政府采购、项目执行单位选定等，输出直接参与且受影响的商业实体。
- 政府或事业单位作为采购方、委托方、主办方时不输出。
- 被选定、中标或承接项目的商业公司要输出。

### 结果

- 实体数：50
- 有实体文章：25
- judge recall：0.889
- judge precision：0.971
- judge 满分文章：23

### 改善

`温州市壹佳壹文化传媒有限公司` 被追回。

网站制作名单仍保持 0，说明没有重新放开到“名单抽爆”。

已知坏实体没有回来：

- 商品/矿种：`工业硅`、`萤石矿`
- 币种/代币：`KEKIUS`、`狗狗币`
- 个人：`陈德军`、`陈小英`
- 政府/计划名：`新加坡国家人工智能计划`
- 纯娱乐主体：`迪士尼`

### 问题

1. 同向重复实体复现。

氪星晚报中 `阿里巴巴` 出现两行，且同为利好：

- 一行来自电商业务增长。
- 一行来自 `通义千问` 被新加坡国家 AI 计划采用。

按规则应合并。

2. judge 仍不理解 `mapped_from`。

LMArena 文章中，eval 输出：

- `智谱AI` mapped_from `GLM-5`
- `百度` mapped_from `文心5.0`
- `阿里巴巴` mapped_from `Qwen3.5`
- `月之暗面` mapped_from `Kimi K2.5`

但 judge 只收到实体名称列表，不知道产品到母公司的映射，因此仍把这些公司误判为 extra。

## eval_5：增加确定性合并和 mapped_from-aware judge

### 代码改动

#### 1. Eval 输出后处理合并

在 `entity_eval/run.py` 中增加确定性合并逻辑：

合并 key：

```
doc_id + entity + entity_sentiment
```

合并规则：

- `mapped_from` 去重后用 `，` 拼接。
- `sentiment_reason` 去重后用 `；` 拼接。
- `impact_level` 取更高等级：`大 > 中 > 小 > 空`。
- 不合并方向不同的同一实体。

summary 中新增：

```json
"total_entities_before_merge": 54
```

#### 2. Judge 输入从名称列表改成完整记录

原来 judge 只接收：

```json
["字节跳动", "智谱AI", "百度", "阿里巴巴", "月之暗面"]
```

现在改为接收完整记录：

```json
[
  {
    "entity": "智谱AI",
    "mapped_from": "GLM-5",
    "entity_sentiment": "利好",
    "sentiment_reason": "GLM-5登榜LMArena，提升品牌知名度"
  }
]
```

judge prompt 同步要求：

- 如果 `mapped_from` 出现在原文，且能合理映射到 `entity`，不要把母公司判为 extra。

### 结果

- 合并前实体数：54
- 合并后实体数：53
- 有实体文章：25
- judge recall：0.884
- judge precision：1.000
- judge extra：0
- judge 满分文章：25/30

### 改善

1. 同向重复实体被合并。

氪星晚报中 `阿里巴巴` 合并为一行：

```text
entity: 阿里巴巴
mapped_from: 通义千问
entity_sentiment: 利好
impact_level: 中
sentiment_reason: 第二财季电商客户管理收入同比增长10%，即时零售业务收入同比增长60%，业绩增长强劲；新加坡国家AI计划转向采用阿里千问开源架构，体现技术认可，利好AI业务
```

2. LMArena 评测问题明显改善。

`judge_5` 中 extra 总数为 0，说明 mapped_from-aware judge 解决了“产品名在原文、母公司在输出中被误判为 extra”的问题。

3. 核心抽多问题继续被压住。

网站制作公司名单仍为 0 实体。

已知坏实体仍未出现。

### 剩余问题

#### 1. judge missed 中仍有口径冲突

`judge_5` 剩余 missed 主要集中在：

- 网站制作公司名单：judge 仍要求 `上海雍熙`、`W+K`、`TBWA` 等，但这些属于名单/案例，不应抽。
- 德赛西威/小鹏汽车：只是泛泛客户关系，当前不抽符合口径。
- 山东儒原文章：judge 要求 `胖东来`、`嘉百乐`、`步步高` 等，但当前只保留主角 `山东儒原`，符合“直接舆情主体优先”的方向。
- 三全食品文章：judge 要求 `海南三全食品科技有限公司`，属于别名/子公司粒度问题。
- 氪星晚报：judge 要求 `比亚迪`、`曙光股份`、`宁德时代`，这些偏泛泛回应或合作背景，是否抽取取决于后续口径。

#### 2. Meta 边界仍可讨论

`eval_4` 抽取了 `Meta` 利空，因为新加坡国家 AI 计划放弃 Meta 模型。

`eval_5` 没有抽取 `Meta`，judge 也没有再要求它。

该边界可以暂时接受，但如果后续希望覆盖“被客户/国家项目弃用”的商业实体，则应补充规则。

## 当前结论

`batch_30_eval_5` / `batch_30_judge_5` 是目前最稳的版本，建议作为当前 baseline。

理由：

- 实体数量从 eval_1 的 133 降到 eval_5 的 53，抽多问题明显缓解。
- precision 从 judge_1 的 0.883 提升到 judge_5 的 1.000。
- LMArena 的 mapped_from 误判问题已解决。
- 网站制作名单没有重新抽爆。
- 商品、币种、个人、政府机构等已知坏实体没有回来。
- 同向重复实体已有确定性合并。

## 下一步建议

### 短期

1. 不再继续在 30 条样本上大幅调 prompt，避免过拟合。
2. 扩大到 100 条样本，观察是否出现新的系统性问题。
3. 对 `judge` 增加确定性后处理，过滤明显不应计入 missed 的名单/案例/来源类对象。

### 中期

1. 增加别名/简称/子公司容忍策略。

典型问题：

- `三全食品` vs `海南三全食品科技有限公司`
- `农业银行` vs `农行`
- `包钢股份` vs `内蒙古包钢钢联股份有限公司`

2. 明确交易参与方粒度。

需要决定是否输出：

- 重组投资人
- 被收购标的
- 一般供应商/客户
- 被弃用模型或产品的母公司

3. 增加字段扩展。

可考虑：

- `risk_type`
- `event_summary`
- `event_role`：主体 / 交易对手 / 投资人 / 供应商 / 客户 / 来源方

`event_role` 可以帮助解决“抽主角还是抽所有参与方”的边界问题。
